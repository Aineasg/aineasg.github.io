Debug story: VPN vs. VM bridge

Goal: run an LLM in a QEMU VM with every packet forced through a VPN with a kill-switch.

Problem: the VPN's TUN interface and QEMU's virtual bridge were fighting over routing.

Fix: manual iptables rules plus a dedicated network namespace. Slow going — and it taught me more about Linux routing than any lab.

How I build: I reverse-engineer the hardware, plan the architecture and define exactly how it should behave — then direct AI to write the code, and test it on real hardware until it works. Rust is my language of choice for the speed and memory safety.

Tongfang / Aistone Control Centre

Native Linux control app for niche enthusiast laptops — written in Rust, open source.

RustACPIEmbedded ControllerReverse engineeringAI-assisted dev
View on GitHub ↗
The problem

Tongfang and Aistone laptops ship with limited official control software and no proper way to tune fans, power or lighting from Linux.

What I did

Read the ACPI tables, watched EC register values change as I toggled settings and mapped what each one controls. Then I specced the app, directed the AI-written Rust code and tested every change on the hardware.

The result

Custom fan curves by temperature, power-profile switching and keyboard backlight control — all from one native app, shipped and open source.

Why it matters for a network role: it's the same loop as troubleshooting a link — observe, form a theory, test one change, document it.
